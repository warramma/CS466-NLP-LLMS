**Creating a LangGraph Agent (5 quick bullets)**  

1. **Define the graph nodes** – Write Python callables (or LangChain components) that represent each step of your workflow (e.g., tool‑call, LLM query, data fetch).  
2. **Specify the edges** – Use `Graph.add_edge(source, target, condition)` (or the `StateGraph` DSL) to declare how the output/state of one node routes to the next.  
3. **Declare the state schema** – Create a `TypedDict` (or Pydantic model) that lists all variables the graph will read/write (e.g., `question`, `answer`, `tool_result`).  
4. **Instantiate the graph** – Call `graph = StateGraph(state_schema)` and register the node functions with `graph.add_node(name, fn)`. Then compile with `graph.compile()`. 
5. **Run the agent** – Invoke the compiled graph with an initial state (`graph.invoke({"question": "…"})`) or stream it (`graph.stream(...)`) to get the agent’s response, handling retries or human‑in‑the‑loop as needed.

### Attention Mechanism in Transformers  

- **Core idea:** Each token in a sequence computes a weighted sum of *all* other token representations, allowing the model to “pay attention” to the most relevant parts of the input when producing an output.  
- **Queries, Keys, Values:** For every token, a **query** vector is matched against **key** vectors of all tokens; the resulting similarity scores (scaled dot‑products) areturned into attention weights (softmax), which are then applied to the **value** vectors to produce the attended representation.  
- **Multi‑head:** The process is repeated in parallel across several “heads,” each learning different relational patterns; the heads are concatenated and linearly projectedback to the model dimension.  
- **Self‑attention vs. cross‑attention:** In encoder layers, queries, keys, and values all come from the same sequence (self‑attention). In decoder‑to‑encoder layers, queries come from the decoder while keys/values come from the encoder (cross‑attention), letting the decoder focus on relevant encoder positions.  
- **Benefits:** Enables direct, content‑based interactions between any pair of positions regardless of distance, leading to better long‑range dependency modeling and highlyparallelizable computation compared to recurrent architectures.
